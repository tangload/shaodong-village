# 邵东村 · 文化 IP 与乡村振兴展示网站

一个关于江苏宜兴湖㳇镇邵东村的综合门户单页网站，主打**贡茶古道文化 IP、古琴大师成公亮故事、山间古韵与乡村振兴实践**。纯静态、零依赖、响应式，可直接用 GitHub Pages 免费托管。

## 站点内容

页面自上而下分为以下板块：

- **村情速览**：人口、面积、竹林、区位等基础画像（含三面环山、溪水纵横地貌特征）；更完整的村庄概况见二级页 `cunqing.html`（主页该板块已加「查看村情详情 →」入口）
- **贡茶古道**：阳羡贡茶历史脉络、境会亭、廿三湾、赐福寺，以及白居易《夜闻贾常州崔湖州茶山境会亭欢宴》诗引；更详实的历史脉络、诗章撷英、名物考与基于茶学三典的考证说明见二级页 `gongcha.html`（主页该板块已加「查看贡茶历史详情 →」入口）
- **琴声里的廿三湾**：古琴大师成公亮与邵坞的十四天交集
- **山间古韵**：项羽传说、青隐寺、东岭水库、村史源流
- **物产与体验**：毛竹、笋干、阳羡茶、山泉 + 徒步溯溪线路
- **三张王牌 / 三个真问题**：机遇与挑战并陈——资源稀缺性、流量自然性、底蕴厚度，对比有流量没留量、配套薄弱+灾后恢复、人口空心化与人才断档
- **乡村振兴**：邵东村的振兴实践，两年主线与分步实施路线图（弱化个人署名，聚焦村落行动）

## 发布到 GitHub Pages（后续步骤）

1. 在 GitHub 新建一个公开仓库（建议名 `shaodong-village` 或 `shaodong-village-site`）。
2. 将本目录内容推送到 `main` 分支：
   ```bash
   git init
   git add .
   git commit -m "邵东村网站初版"
   git branch -M main
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```
3. 仓库 → **Settings → Pages → Build and deployment → Source 选择 "GitHub Actions"**。
4. 推送后 Actions 会自动构建并发布，几分钟即可在 `https://<用户名>.github.io/<仓库名>/` 访问。

> 若不想要 Action 自动部署，也可在 Pages 设置里直接选 "Deploy from a branch → main → /(root)"，无需 `deploy.yml`。

## 访问统计（访客数 / 总访问量）

> **2026-10 更新**：原「不蒜子（busuanzi）」旧端点 `busuanzi.ibruce.info` 的计数 API 已彻底失效（脚本能加载但取不到数字，页脚恒显「—」）。现改用 **vercount.one**——一款开源、兼容不蒜子标签的计数服务，切换只需改一行脚本地址。

页脚展示的「访客数」与「总访问量」由 **vercount.one** 计数服务实现，纯前端、零依赖。实现方式是页面中保留一行远程脚本与两个占位 `<span>`：

- 脚本：`https://events.vercount.one/js`（位于 `index.html` 末尾，`defer` 加载）
- 占位：`id="busuanzi_value_site_uv"`（访客数）、`id="busuanzi_value_site_pv"`（总访问量）——**沿用旧不蒜子标签 ID，vercount 原生兼容，无需改动页面结构**

**如何保留并继续累计：**

1. **数据不在 index.html 里**，而是存储在 vercount.one 服务器，分两级计数：
   - **站点级（即页脚的「访客数 / 总访问量」）**：按「域名」聚合。同一域名下所有页面（主页 + 子页面）的访问会自动汇总到同一个计数器，无需手动合并。
   - **页面级**：按「域名 + 完整路径」单独计数，每个子页各自累计、互不干扰。
2. **子页面自动汇总的前提**：子页面也要引入同一行 vercount 脚本，且部署在**同一域名 / 同一 GitHub Pages 站点**下（不是另开一个仓库）。满足后，主页页脚的「访客数 / 总访问量」自然会包含子页面访问。
3. 重新上传 `index.html` **只要保留脚本与两个 span，且部署域名不变**，历史统计自动延续、不会清零（vercount 按域名聚合）。
4. **只有换域名 / 换子域名 / 另开仓库**才会使站点级数据重置（旧域名数据不可迁移、不可合并）；仅改动路径不影响站点级汇总，只影响页面级计数。
5. 本地 `file://` 直接双击预览会被计入 `file://` 这个独立 key，**不计入线上访问量**，属正常现象。
6. **无法做到的事**：vercount 免费公共服务无跨页数据 API，你**不能**在主页上"分别显示每个子页各自访问了多少"——想看某子页访问量就进该子页看它自己的页面级统计。

**后续建议（数据自主）：** vercount.one 为免费社区公共服务、数据暂不在己手，将来若不稳定可 fork 其开源仓库自托管（后端 Go + Redis，部署到 Vercel / Docker；或自行用 Cloudflare Workers + KV 重写一个兼容计数器）。切换**只需改 `index.html` 末尾那一行脚本地址**，页面结构不变；但计数会从 0 重新累计（旧服务数据无法同步）。
